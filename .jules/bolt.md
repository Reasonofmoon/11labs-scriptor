## 2024-05-18 - [Web Audio API Render Optimization & Hydration Fix]
**Learning:** Web Audio API frequency data is populated into a `Uint8Array`, strictly returning integer values from 0 to 255. This bounded range allows for exact pre-calculation and caching of corresponding rendering objects (like CanvasGradient) to avoid high object allocation and Garbage Collection (GC) pressure inside the `requestAnimationFrame` render loop. Also, using `Math.random()` inside React render cycles (like in the idle visualizer bars) causes Next.js hydration mismatches between the server and client.
**Action:** When implementing canvas rendering loops over large datasets, look for opportunities to pre-calculate values if the input domain is bounded (like 0-255 for `Uint8Array`). Always initialize cache arrays outside the `requestAnimationFrame` callback. Replace `Math.random()` in render cycles with deterministic constant arrays to prevent hydration mismatches.
