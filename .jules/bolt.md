## 2024-05-14 - Canvas Gradient Caching and Next.js Hydration Patterns
**Learning:** For HTML5 Canvas animations in React `useEffect` loops (like Audio Visualizers), recreating `LinearGradient` objects on every frame inside a `requestAnimationFrame` loop (e.g. `analyser.getByteFrequencyData`) is highly inefficient and creates significant garbage collection overhead. Pre-calculating them outside the loop and caching them into an array indexed by values (0-255) dramatically reduces object creation and CPU usage. Additionally, using `Math.random()` during render for idle states causes strict React purity violations and Next.js hydration mismatches. Deterministic constant arrays should always be used for static mock data rendered in Next.js apps to satisfy strict React purity rules.
**Action:** When implementing high-frequency Canvas animations mapping byte arrays (0-255), always cache gradients or complex objects outside the animation loop using a pre-calculated index map. Always replace `Math.random()` in React component render bodies with deterministic values (e.g. constant arrays) to avoid hydration errors and satisfy strict React purity checks.
