## 2025-07-07 - Canvas Animation GC Bottlenecks & Rendering Optimizations
**Learning:** The Visualizer component re-creates `CanvasGradient` objects every frame within `requestAnimationFrame` using dynamic calculations based on Web Audio API data. Since `Uint8Array` provides bounded integers [0-255], creating new gradient objects inline causes massive continuous memory allocation and subsequent Garbage Collection (GC) pressure. Additionally, Next.js hydration fails if `Math.random()` is used to render visual states on the server vs client.
**Action:** Pre-calculate the 256 possible gradient configurations into a cached array completely outside the `requestAnimationFrame` loop. Replace `Math.random()` with deterministic constant arrays to prevent hydration mismatches. Add short-circuit logic `if (x > canvas.width) break;` to prevent off-screen calculations during large dataset renders.
