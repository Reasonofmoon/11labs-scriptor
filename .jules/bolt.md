## 2024-11-20 - [Performance Optimization] Pre-calculate Canvas Gradients and Fix Hydration
**Learning:** In HTML5 Canvas rendering loops with high-frequency updates (e.g., audio visualization using `requestAnimationFrame`), recreating objects like `CanvasGradient` on every frame causes significant Garbage Collection (GC) pressure and frame drops. Also, using `Math.random()` for initial UI state causes hydration mismatches in Next.js between server and client.
**Action:** When implementing visualizers, pre-calculate bounded-range objects (like 0-255 Web Audio API frequency gradients) outside the animation loop. Use deterministic constant arrays for idle UI states instead of random numbers. Add short-circuit logic (`if (x > canvas.width) break;`) to avoid off-screen rendering.
