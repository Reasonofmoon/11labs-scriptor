## 2024-05-20 - CanvasGradient Pre-calculation and React Hydration fixes
**Learning:** In Web Audio applications using Canvas, creating `CanvasGradient` objects inside the `requestAnimationFrame` loop for every frequency bar (e.g., thousands per second) creates immense Object Allocation and Garbage Collection (GC) pressure which severely degrades rendering frame rates. Also, using `Math.random()` in React component render cycles (like idle visualizer bars) causes Next.js hydration mismatches between server and client.
**Action:** Pre-calculate `CanvasGradient` objects outside the render loop for the finite range of Web Audio bytes (0-255 in `Uint8Array`) and reuse them. Handle zero-height edge cases with `Math.max(1, height)` to prevent `DOMException: The coordinates provided are not finite.`. Always use deterministic data sources (like constant arrays) for initial component render states to prevent hydration mismatches.
