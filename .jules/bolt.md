## 2024-05-24 - Optimize Canvas rendering GC pressure and fix hydration mismatch
**Learning:** Found high Garbage Collection (GC) pressure inside the `Visualizer` component due to creating `CanvasGradient` objects inside the `requestAnimationFrame` loop. The values come from a `Uint8Array`, meaning there are only 256 possible integer values (0 to 255). We can pre-calculate and cache these objects outside the loop. Also discovered `Math.random()` inside the React render cycle for the idle state which causes Next.js hydration mismatches between the server and client.
**Action:** Always pre-calculate and cache rendering objects in Canvas loops when the input domain is bounded (like 0-255 for Web Audio API frequency data). Replace `Math.random()` in React render cycles with deterministic constant arrays or move it to a `useEffect` hook. Add short-circuit logic `if (x > canvas.width) break;` in Canvas loops to prevent rendering off-screen elements.
