## 2024-10-04 - Caching bounded Web Audio API canvas objects
**Learning:** Web Audio API frequency data is populated into a `Uint8Array`, strictly returning integer values from 0 to 255. This bounded range allows for exact pre-calculation and caching of corresponding rendering objects (like CanvasGradient) to avoid high object allocation and Garbage Collection (GC) pressure. Additionally, iterating over large datasets in HTML5 Canvas loops should short-circuit off-screen element rendering (e.g., `if (x > canvas.width) break;`). Also confirmed `Math.random()` in React render cycles causes Next.js hydration mismatches.
**Action:** When implementing canvas rendering loops over Web Audio API data, initialize a cache array strictly outside the `requestAnimationFrame` callback to avoid unnecessary recreation on every frame, handle zero-height edge cases (e.g., `Math.max(1, height)`) for finite coordinates, and implement short-circuit break conditions for off-screen objects. Replace non-deterministic `Math.random()` visual states with constant arrays.
