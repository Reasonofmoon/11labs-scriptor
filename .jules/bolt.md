## 2024-07-04 - Canvas Render Loop Optimization & GC Pressure
**Learning:** Web Audio API frequency data is populated into a `Uint8Array`, meaning values strictly range from 0 to 255. In `Visualizer.tsx`, creating a new `CanvasGradient` for every frequency bin, on every `requestAnimationFrame` tick, creates immense Garbage Collection (GC) pressure. Because the possible heights are strictly bounded (256 discrete values), we can pre-calculate and cache exactly 256 gradient objects outside the render loop. Also learned that when pre-calculating canvas optimizations, it's critical to handle zero-height edge cases (e.g. `height || 1` or `Math.max(1, height)`) to ensure coordinates are finite and avoid `DOMException: The coordinates provided are not finite.`.
**Action:** Always inspect HTML5 Canvas rendering loops for high-frequency object allocation (like gradients or complex paths) and check if the input data space is bounded (like `Uint8Array`) to enable exact pre-calculation and caching outside the loop.
