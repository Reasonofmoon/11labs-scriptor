## 2024-05-24 - Canvas Optimization in Visualizer
**Learning:** In HTML5 Canvas rendering loops iterating over large datasets like Web Audio frequency arrays, creating new objects (like `CanvasGradient`) inside the `requestAnimationFrame` loop causes high object allocation and Garbage Collection (GC) pressure. Since Web Audio API frequency data is bounded (integer values from 0 to 255), we can pre-calculate and cache all possible rendering objects. Additionally, `Math.random()` inside React render cycles (like in idle visualizer bars) causes Next.js hydration mismatches between the server and client.
**Action:** When working with Canvas and Web Audio API, pre-calculate and cache rendering objects for bounded data. Avoid `Math.random()` for visual states in Next.js, and instead replace them with deterministic constant arrays.
