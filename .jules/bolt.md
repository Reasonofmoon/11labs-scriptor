## 2024-05-18 - Canvas Rendering Bottlenecks & Next.js React Hydration Purity
**Learning:** In HTML5 Canvas animations (`requestAnimationFrame`), calling context methods that instantiate objects (like `ctx.createLinearGradient()`) on every frame for multiple elements (like frequency bars) causes significant garbage collection overhead. Since `AnalyserNode` `Uint8Array` data yields bounded integer values (0-255), we can pre-calculate and cache these visual objects perfectly. Furthermore, using impure functions like `Math.random()` during functional component rendering to simulate "random" states leads to severe Next.js hydration mismatches and violates strict React purity rules.
**Action:** Always pre-calculate expensive objects (like gradients or complex paths) using bounded data ranges outside the render loop for Canvas animations. Use deterministic constants (e.g., arrays of fixed values) instead of `Math.random()` during component initialization/rendering to ensure SSR hydration matching and React purity. Wrap static UI pieces in `React.memo` to prevent re-renders on every parent state change.
