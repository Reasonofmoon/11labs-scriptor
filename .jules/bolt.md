## 2024-03-24 - React Purity and Canvas Optimization
**Learning:** The project strictly enforces React purity rules via linting, which flags impure functions like `Math.random()` used during render (e.g., in inline styles). Using `Math.random()` in Next.js also leads to hydration mismatches. For HTML5 Canvas animations driven by the Web Audio API in React, re-creating objects like `LinearGradient` inside the `requestAnimationFrame` loop on every frame causes unnecessary overhead. Since Web Audio frequency bins return bounded integers (0-255), we can completely pre-calculate rendering artifacts.
**Action:** Use a deterministic constant array for random-looking idle states instead of `Math.random()` to satisfy both linting and hydration constraints. Pre-calculate and cache expensive canvas objects (like gradients) indexed by bounded Web Audio values (0-255) outside the render loop, and apply bounds checks (`if (x > canvas.width) break;`) to early-exit processing of off-screen elements.
