## 2024-05-18 - Canvas Context Pre-calculation & Next.js Hydration
**Learning:** In Web Audio API applications, `analyser.getByteFrequencyData` populates a `Uint8Array`, strictly returning integers from 0 to 255. Dynamically creating `CanvasGradient` objects inside the `requestAnimationFrame` loop (e.g., `ctx.createLinearGradient`) for every frame causes massive Garbage Collection (GC) pressure and performance drops. Furthermore, using `Math.random()` to generate idle visualizer heights causes Next.js hydration mismatches between the server and client.
**Action:** Pre-calculate and cache the 256 possible `CanvasGradient` instances outside the render loop. Always handle edge cases for zero-height rendering (`Math.max(1, height)`) to prevent `DOMException: The coordinates provided are not finite.`. In addition, use a constant, deterministic array for visual states (like idle bars) to avoid hydration errors.
