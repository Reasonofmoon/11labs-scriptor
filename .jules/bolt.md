## 2024-06-11 - Optimize Canvas Garbage Collection & Hydration Mismatches
**Learning:** High frequency audio visualization inside `requestAnimationFrame` creates massive Garbage Collection (GC) pressure when instantiating new objects (like `CanvasGradient`) 60 times a second. Also, using `Math.random()` in React rendering causes hydration mismatches between Server Side Rendering and Client Side Rendering in Next.js. The Web Audio API's `getByteFrequencyData` populates a `Uint8Array`, meaning values strictly range from 0 to 255.
**Action:** When working with Web Audio API frequency arrays and Canvas, pre-calculate visual assets like gradients into an array cache of 256 elements. This bounds memory and eliminates runtime GC spikes. Replace `Math.random()` in visual styles with deterministic values (e.g. static arrays or seeded hash logic) to maintain SSR consistency.
