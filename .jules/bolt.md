## 2024-05-15 - Visualizer Canvas Optimization
**Learning:** In HTML5 Canvas rendering loops with high frequency updates (like audio analyzers), dynamically creating `CanvasGradient` objects inside `requestAnimationFrame` creates severe GC pressure and frame drops. Because Web Audio API `Uint8Array` returns strictly integer values from 0-255, we can pre-calculate and cache exactly 256 gradient objects outside the render loop. Also, rendering off-screen canvas items causes unnecessary calculation overhead. Finally, using `Math.random()` inside React components for visual states (like idle bars) leads to Next.js server-client hydration mismatches.
**Action:** Always pre-calculate and cache Canvas rendering objects when iterating over bounded ranges. Use short-circuit break conditions (`if (x > canvas.width) break;`) for off-screen canvas elements. Replace `Math.random()` with deterministic constant arrays for cosmetic idle states in Next.js applications.
