## 2025-03-05 - Optimize Web Audio Canvas Rendering and Fix Next.js Hydration Mismatch
**Learning:** In HTML5 Canvas rendering loops iterating over Web Audio API `Uint8Array` frequency data, creating new `CanvasGradient` objects inside `requestAnimationFrame` causes massive Garbage Collection (GC) pressure. Since the data values are strictly bounded integers from 0 to 255, we can pre-calculate and cache exactly 256 gradient objects outside the animation loop. Also, using `Math.random()` to generate visual states (like idle visualizer bars) inside a Next.js component causes hydration mismatches between the server and client.
**Action:** When working with Web Audio API `Uint8Array` data for Canvas visualization, pre-calculate visual mapping objects (like gradients) based on the 0-255 bounds. Implement a short-circuit break condition (`if (x > canvas.width) break;`) to avoid calculating and rendering off-screen elements. Replace `Math.random()` in visual states with a deterministic constant array or handle it correctly with useEffect for client-only rendering.
