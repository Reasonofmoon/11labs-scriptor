## 2024-05-24 - Visualizer GC Optimization & Hydration Fix
**Learning:** The Web Audio API `AnalyserNode.getByteFrequencyData` populates a `Uint8Array`, meaning values strictly bounded from 0 to 255. In the `Visualizer.tsx` component, `ctx.createLinearGradient()` was being called on every animation frame for every frequency bin, creating massive GC pressure for thousands of gradient objects per second. Furthermore, an idle visualization state used `Math.random()` to generate heights, which caused a Next.js hydration mismatch between the server rendering and the client hydration.
**Action:** Always exploit the bounded integer nature of `Uint8Array` data to pre-calculate and cache expensive Canvas rendering objects (like `CanvasGradient`) ahead of `requestAnimationFrame` loops. Never use `Math.random()` inside a React render cycle for default/idle component states; replace with deterministic array constants.
