## 2024-05-15 - React Render Hydration and Canvas Object Instantiation
**Learning:** Next.js throws hydration errors if `Math.random()` is used to calculate visual properties during render cycles (e.g. initial height of idle animation bars). Furthermore, instantiating `CanvasGradient` objects inside a `requestAnimationFrame` loop creates immense unnecessary GC overhead. Since `Web Audio API`'s `Uint8Array` strictly outputs integers from 0 to 255, we can perfectly pre-cache 256 gradient permutations without ever risking OOM or map lookups.
**Action:** Always replace `Math.random()` used in initial UI styles with constant arrays to ensure deterministic SSR and hydration. Always extract repetitive object creation in HTML5 canvas rendering loops out into a deterministic cache bounded by absolute theoretical bounds of the input space.
